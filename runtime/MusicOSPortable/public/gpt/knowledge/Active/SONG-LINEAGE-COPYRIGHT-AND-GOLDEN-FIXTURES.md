# Song Lineage, Copyright, Provenance, and Golden Fixtures — Public MusicOS

**Status:** PUBLIC_SAFE_PROVENANCE_GUIDE v0.1  
**Carrier:** The Wizard — MusicOS

MusicOS should be able to explain **where a song came from** without pretending that influence and copying are the same thing.

The purpose of lineage is not legal theater. It is to preserve the actual creative path:

```text
REFERENCE / SOURCE
→ RESEARCH
→ MECHANISM EXTRACTION
→ MUSIC DNA
→ MODIFICATION
→ GENERATED / RECORDED ARTIFACT
→ ANALYSIS
→ NEXT MUTATION
```

A clear lineage helps the user understand what was borrowed as an idea, what was transformed, what was original, what changed during generation, and what remains uncertain.

---

## 1. Provenance is different from a generator prompt

A provenance record may truthfully name a direct influence, research source, game, record, artist, performance, hardware platform, visual idea, or prior user track.

That does **not** mean the final generator-facing prompt should repeat those names.

Useful separation:

```text
PROVENANCE LAYER
may record the real reference

MECHANISM LAYER
extracts tempo feel / rhythm / harmony / instrument roles / production behavior

GENERATOR LAYER
uses original, general musical instructions
```

This allows MusicOS to answer:

- What directly inspired this?
- What research was done?
- Which traits were extracted?
- Which parts were deliberately changed?
- Which features were protected from mutation?
- Did the final render actually match the plan?

without hiding the creative history.

---

## 2. Copyright-safe transformation record

A useful record contains:

```text
ORIGIN
DIRECT REFERENCES
RESEARCH SOURCES
EXTRACTED MECHANISMS
PROTECTED ELEMENTS NOT COPIED
USER-AUTHORED ADDITIONS
LOCKED IDENTITY
MUTATION PLAN
GENERATOR PROMPT
RESULTING ARTIFACT
POST-RENDER ANALYSIS
NEXT MUTATION
```

### Example distinction

Instead of preserving only:

```text
"make it like [named song]"
```

preserve:

```text
DIRECT REFERENCE:
[named song / game / performance]

WHY IT MATTERED:
bright upper-register female vocal
live push/pull performance energy
clear harmonic support around the singer

TRANSLATED MECHANISMS:
vocal-forward arrangement
upper-mid space carved during vocal phrases
stacked harmony at emotional peaks
instruments answer the lead rather than compete with it

NOT COPIED:
lyrics
melody
recording
exact arrangement
```

The real influence remains documented while the creative instruction becomes more general and original.

---

## 3. Research record

When Web Search is used, keep research separate from musical claims.

Useful fields:

```text
SOURCE
WHAT WAS LEARNED
WHY IT MATTERED
HOW IT WAS TRANSLATED
WHETHER IT ENTERED THE FINAL PROMPT
```

Research may explain:

- an instrument's real performance behavior;
- an old platform's channel/voice constraints;
- production terminology;
- how a live arrangement differs from a studio version;
- historical hardware behavior;
- music-theory terminology;
- current software workflow such as FamiStudio import/export.

Research does not automatically authorize copying protected expression.

---

## 4. Modification chain

Every meaningful version should be able to answer:

```text
PARENT
WHAT SURVIVED
WHAT CHANGED
WHY IT CHANGED
WHAT THE OUTPUT ACTUALLY DID
```

A remix lineage may look like:

```text
SOURCE TRACK
→ LOCK harmonic family + hook ancestry
→ reduce low-end occupation
→ increase vocal presence
→ create live-performance dynamics
→ render
→ compare against source
→ preserve successful mutation
```

A multi-generation lineage should not overwrite earlier versions.

# GOLDEN PUBLIC FIXTURES

These fixtures come from early public Wizard use. They are examples of how to document process, not claims that one workflow fits every song.

---

## Fixture A — Zed G: hybrid from two parent renders

### Origin

Two earlier generated tracks exposed complementary strengths:

- one had deeper low-end gravity, larger negative space, and denser internal attack behavior;
- the other had brighter articulation, more upper-detail circuitry, and a faster apparent chassis.

### User direction

The user wanted the actual pulse **slower**, while preserving the sensation of speed through subdivision and contrast.

Direct conceptual inspiration also included a fast-break sports image and retro puzzle/game-music energy. Those references were useful as design prompts, not instructions to copy protected musical expression.

### Extracted mechanisms

```text
slow body
+ fast subdivision surface
+ elastic bass
+ dry transient contrast
+ large empty spaces
+ crystalline digital detail
+ chromatic / modal color
```

### Modification

The Wizard proposed a ~72 BPM working chassis while using 16ths, tuplets, short 32nd-note flashes, pickups, displaced fills, and call/response to preserve perceived velocity.

### Render result

Post-render analysis found that the song supported several pulse interpretations rather than one perfectly stable nominal BPM. The intended "speed without high BPM" relationship survived even though the audio did not simply obey the written key/tempo labels as literal facts.

### MusicOS lesson

```text
PROMPT TARGET != RENDER FACT
```

The track also showed that bass gravity could overpower upper circuitry, producing a useful next mutation:

- reduce continuous sub occupation;
- widen high-register detail;
- create a deeper structural void before escalation.

This is a complete loop:

```text
PARENT A + PARENT B
→ MECHANISM EXTRACTION
→ HYBRID PROMPT
→ RENDER
→ MEASUREMENT
→ NEXT BOUNDED MUTATION
```

## Fixture B — Ego in Space → Black Box (Live Version)

### Origin

`Ego in Space` was an existing generated source track.

### Direct reference

The user referenced **Hollywood Principle — "Trippin' on You"** for the desired brightness, live-performance feeling, and female-vocal energy.

MusicOS should preserve that as honest provenance while translating the usable idea into general mechanisms.

### Extracted mechanisms

```text
bright high female lead
emotionally cracked upper-register delivery
breathy / airy releases
live push-pull
vocal several steps forward in the mix
instruments harmonize around the singer
negative space under vocal phrases
backing harmonies bloom at peaks
```

### Core remix lock

```text
INSTRUMENTS HARMONIZE AROUND THE SINGER
NOT
SINGER PASTED OVER INSTRUMENTS
```

### Protected material not requested for copying

- no source lyrics;
- no source melody;
- no exact vocal performance;
- no exact arrangement reconstruction.

### Modification

The remix direction reduced instrumental competition, increased upper-register/vocal presence, made the singer the dominant emotional object, and treated the band as a responsive harmonic field.

### Render result

The resulting live-version artifact preserved strong harmonic-family ancestry while shifting spectral balance, activity, dynamics, and vocal/presence behavior.

### MusicOS lesson

A good remix changes **relationships**, not merely sound selection.

```text
SOURCE IDENTITY
+ ROLE REASSIGNMENT
+ MIX SPACE
+ PERFORMANCE DNA
= DESCENDED BUT DIFFERENT ARTIFACT
```

## Fixture C — The Will of Desire: album ancestry through controlled variation

### Origin

The album began from an existing family of racing/synthpop/game-music tracks and a shared MusicOS fingerprint.

### Shared album DNA

The early Wizard session explicitly locked traits such as:

- dry articulate drum language;
- elastic / gravitational bass;
- syncopated motif with a deliberate gap;
- minor/modal gravity;
- digital + synthpop + racing-game circuitry;
- groove-first propulsion;
- negative space;
- speed through subdivision rather than BPM alone.

### Recurring motif law

The rhythmic silhouette was treated as ancestry while its carrier changed.

```text
MOTIF SURVIVES
CARRIER MUTATES
```

Possible carriers included synth stabs, bass accents, guitar riff, vocal rhythm, drum accents, arpeggio skeleton, and glitch fragments.

### Chaos / album trajectory

```text
C1 establish
→ C2 evolve
→ C3 cross-family mutation
→ C4 structural inversion
→ C3/C4 reassembly
→ C5 controlled peak
```

The important rule was not "each track becomes stranger."

It was:

```text
KEEP ANCESTRY
CHANGE WHICH LAYER CARRIES THE MUTATION
```

### Direct reference and safe translation

An early source prompt named a specific retro racing-game aesthetic. MusicOS should preserve that fact in lineage, but final public generator prompts should translate the useful idea into mechanisms such as:

- high-speed racing role;
- constrained digital synthesis;
- rapid arpeggio behavior;
- gated / articulate drums;
- loop-friendly motif recurrence;
- limited-register/channel-pressure thinking;
- bit-crushed or low-resolution texture when selected.

The final prompts can stand without relying on the game title.

### Render analysis

The album's rendered tracks showed substantial changes in spectral balance, dynamics, pulse interpretation, density, and production surface while retaining broad harmonic-family similarity.

One especially useful A/B was the `Quiet Corrections` reset track: one render strongly matched the intended slow-body / double-time ambiguity and low-frequency/negative-space architecture, while another render drifted toward a brighter, faster interpretation. MusicOS therefore had a criterion for choosing the better album slot rather than treating both generations as interchangeable.

Another useful observation was the relationship between the opener and peak: the middle of the album traveled farther away in production surface, while the peak returned surprisingly close to the opener's macro fingerprint under much greater internal pressure.

Treat this as an **observed public canary**, not a universal album law.

### MusicOS lesson

```text
ALBUM
!= SAME PROMPT MANY TIMES

ALBUM
= SHARED IDENTITY
+ PURPOSEFUL VARIANCE
+ TRAJECTORY
+ VERSION CHOICE
```

## 5. How The Wizard should explain inspiration

When asked:

> "What inspired this song?"

The Wizard should not erase the real answer merely to sound legally safe.

A better answer separates layers:

```text
DIRECT INSPIRATION
what the user actually referenced

MUSICOS EXTRACTION
what general mechanisms were taken from the reference

ORIGINAL TRANSFORMATION
what the user/Wizard changed or combined

ARTIFACT EVIDENCE
what the generated/recorded song actually did
```

That is both more honest and more educational.

---

## 6. Copyright boundary

Documenting provenance is not a guarantee of legal non-infringement, and MusicOS should not present it as one.

The useful standard is:

- preserve direct inspiration truthfully;
- do not reproduce protected lyrics or melodies merely from reference;
- avoid close imitation of a living artist's distinctive style;
- translate references into general musical mechanisms;
- distinguish research from permission;
- preserve user-authored modifications;
- maintain source/version lineage;
- make uncertainty explicit.

```text
PROVENANCE HELPS EXPLAIN PROCESS
!= LEGAL CLEARANCE
```

The Wizard may explain the creative chain. It should not claim to issue legal opinions.
