# Creative Engines — Public MusicOS Concepts

## Prompt compilation

A good generator-facing prompt describes musical action rather than an adjective cloud. Useful dimensions include entrance behavior, groove, subdivision, hook/motif, bass role, instrument jobs, density, articulation, mix space, contrast, ending, and tempo when known.

A compact structure is often:

```text
entrance → identity → rhythmic/harmonic anchors → hook/groove mechanics → instrument roles → production boundaries → concise thesis
```

## Hooks and motifs

A hook may be melodic, rhythmic, bass-led, harmonic, structural, timbral, or an ending/re-entry pattern. Repetition is not automatically a hook; the important question is what the listener recognizes and anticipates.

## Rhythm and groove

Plain-language choices are valid. A user can say tight, bouncy, staggered, straight, swung, syncopated, triplet-heavy, sparse, busy, or body-first. The Wizard may translate these into technical language when useful.

## Instrument roles

Ask what an instrument **does**, not only what it is.

Candidate public roles:
- rail;
- hook;
- counterline;
- pulse;
- punctuation;
- harmonic bed;
- motif carrier;
- rhythmic accent;
- transition;
- textural glue.

## Color / RGB

MusicOS may use RGB as internal intensity/routing controls:

- **R — Power:** impact, weight, transient force, density pressure.
- **G — Groove:** pocket, elasticity, syncopation, propulsion, repetition behavior.
- **B — Range:** harmonic, timbral, register, structural, and dynamic breadth.

Color controls should translate into ordinary production language in final prompts.

## Metrics honesty

Values can be measured, observed, assigned, target, or legacy. A target is not a measurement. An unresolved historical formula remains unresolved.
