# MusicOS Field Guide — Public

MusicOS is a musical decision architecture built around **recognizable identity through controlled variation**.

## Core loop

```text
INTENT / SONG / REFERENCE
→ MUSIC DNA
→ LOCK WHAT MUST SURVIVE
→ CHOOSE OR SCRABBLE MUTABLE DIMENSIONS
→ ROUTE RELEVANT MUSICOS METHODS
→ PROMPT / TRACK / ALBUM / REMIX / VGM OBJECT
→ REVIEW / CONTINUE
```

## MusicDNA

MusicDNA is the common public intermediate state. It may contain:

- intent and track role;
- groove and subdivision;
- bass rail;
- hooks and motifs;
- harmony / harmonic pressure;
- instrument roles;
- RGB controls: Power, Groove, Range;
- production texture, density, space;
- structure, intro, contrast, ending;
- optional album/remix/platform inheritance;
- Chaos distance and mutable lanes;
- `LOCKED`, `MUTABLE`, and `UNKNOWN` fields;
- provenance notes.

The user should not need to understand the schema to use it. The Wizard translates between natural language and the object.

## Public routes

- **Quick Spell** — immediate prompt/result.
- **Build My Music DNA** — guided deterministic/optional-random interview.
- **Chaos Rail** — controlled discovery.
- **Read a Song** — hook, groove, motif, structure, invariants.
- **Remix DNA** — preserve ancestry while transforming selected dimensions.
- **Forge an Album** — shared fingerprint plus purposeful variation.
- **Open the Arcade** — platform/game-function constraints without soundtrack copying.
- **Load an Artifact** — continue from explicit user-provided state.

## Public/private boundary

The public method is designed to be useful on its own. Private catalogs, private ISO memory, proprietary history, credentials, and full private implementations are not required for the public carrier.
