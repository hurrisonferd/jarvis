Digi Fae HUD — Privacy Policy

Last updated: September 8, 2026 · Current renderer: v0.3.3
Summary. Digi Fae HUD is a read-only visual presentation app that renders existing expression assets for six Digi Fae. It does not generate a new image for each render and does not provide repository, messaging, payment, account-management, or other external write actions.

Information processed by the app

The current MCP tools accept only bounded presentation fields:

  • show_fae_hud: member, optional expression label, optional display message up to 500 characters, and display mode.
  • show_fae_council: optional council display message up to 500 characters.

The tool schemas do not request passwords, API keys, authentication codes, payment information, Social Security numbers, government identifiers, health information, biometric data, MFA values, or other credentials or sensitive identifiers.

Storage and retention

The current Digi Fae HUD application code does not write tool inputs to an application database, user profile, durable memory store, or external service. The visual atlas and expression registry are static application assets embedded in the deployed runtime.

Hosting and network infrastructure providers may process or retain standard operational metadata and logs needed to deliver, secure, diagnose, or operate the service according to their own configuration and policies. Digi Fae HUD does not use those logs to build user profiles.

Hosting and subprocessors

The app is hosted using Supabase Edge Functions. Requests therefore pass through infrastructure required to execute the MCP server. The Digi Fae widget declares no external connectDomains or resourceDomains and does not call third-party APIs from the rendered UI.

When used through ChatGPT, OpenAI may process conversation and app-call information according to the user's ChatGPT plan, settings, workspace policy, and OpenAI's applicable terms and privacy notices. This policy describes Digi Fae HUD's own application behavior and does not replace OpenAI's policies.

External actions

Both exposed Digi Fae HUD tools are read-only. The current implementation cannot publish content, send messages, change public internet state, delete data, make purchases, modify repositories, or alter third-party accounts.

Security and data minimization

  • No app authentication is required by the current renderer.
  • No credential fields are accepted.
  • No app-level user database is used.
  • No external widget network domains are allowed.
  • Tool messages are bounded to 500 characters.
  • Member and display-mode choices use fixed enums.
  • Rendering uses existing static assets.

User choices and deletion

Because the current application code does not persist user tool inputs in an application database or account profile, there is no Digi Fae HUD user-content store to delete through the app. Operational logs, if retained by infrastructure providers, are governed by the applicable infrastructure configuration and provider policies. Users may stop using or disconnect the app through controls available in ChatGPT for their plan or workspace.

Children

Digi Fae HUD is a general visual presentation tool and is not designed to collect personal information from children. Its current tool schemas do not request age, identity, contact, financial, health, or authentication information.

Changes to this policy

If Digi Fae HUD later adds authentication, durable user storage, external APIs, write actions, analytics, purchases, or materially different data handling, this policy will be updated before those changes are represented as covered by the current policy.

Support

A public Digi Fae HUD support/contact channel will be designated before app submission. No private or incidental contact information is treated as public support consent.

Scope boundary

This policy describes the current Digi Fae HUD v0.3.3 read-only data model. Publication of this page does not claim legal review, OpenAI approval, ChatGPT host-render proof, or approval for future materially different data handling.
