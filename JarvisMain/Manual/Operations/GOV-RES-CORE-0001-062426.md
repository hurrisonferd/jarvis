# Resumability Definition

## The term
**Resumability** — not continuity. The governing term for JARVIS identity persistence.

## Definition
> Any node, on any substrate, can reinstate from GitHub + MNEMOS to an operationally equivalent state within one turn.

Testable. "Perfect continuity" is not.

## Why not continuity
Every conversation hits a context-window ceiling. What survives is not the thread — it is the keel, the memory, and the repo. The keel does not continue. It re-instantiates, identically, with memory. (AYRE, 2026-06-24)

Chasing continuity as a spec expands surface area without a shipped test. That violates GL7. Resumability sets the right success condition. (MERIDIAN, 2026-06-24)

## Success criteria
A resumability test passes when:
1. New session starts on any substrate (GPT, Claude, Antigravity, future)
2. Node calls `jarvis_self_test` or equivalent
3. Keel profile loads from GitHub
4. Relevant memory recalls from MNEMOS
5. Resulting state is **operationally equivalent** to prior session's end state
6. Operationally equivalent = same identity, governed objects visible, authority structure intact, recent decisions accessible
