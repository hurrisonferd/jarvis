## B — Monolith Carve Plan (proposed, not executed)

A blind split of a 4,620-line file with no test harness is the wrong move — it
risks silently breaking the server (the same class of failure as the `const` bug,
but server-side). Governed sequence instead:

1. **Add a smoke test first.** Boot the FastAPI app in-process, assert every route
   registers and `/` responds. No carve until this exists — it's the safety net.
2. **Extract by seam, one module per commit**, each followed by the smoke test:
   - `handlers/grid.py` (`handle_jarvis_grid`, `neo4j_seed_grid`) — ~330 lines
   - `handlers/neo4j.py` (`handle_jarvis_neo4j`, `neo4j_write_decision`) — ~230
   - `handlers/image.py` (`handle_jarvis_image`, `generate_concept_card`) — ~210
   - `handlers/session.py` (`handle_jarvis_end/log/stats/repo_sync`) — ~200
   - keep route registration + app wiring in `jarvis_mcp_server.py`
3. **GL7 ledger:** each extraction must reduce the root file's line count — record
   before/after in the patch. Net complexity down, not just moved.

Estimate: ~5 commits. Each independently revertable. Do not batch.
