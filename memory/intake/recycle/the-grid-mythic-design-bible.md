# THE GRID Mythic Design Bible

Status: Vision document. Not current build target.

Purpose: define the imaginative north star for THE GRID without confusing it with the next engineering milestone.

## Core Formula

```text
Oda-scale worldbuilding
+ Dantean guided traversal
+ Tron interface language
+ JARVIS governance
= THE GRID
```

The Grid is not just a database UI. It is a navigable symbolic structure for personal knowledge, projects, decisions, memories, and future public spaces.

It should feel vast, coherent, and alive with relationships, but underneath it remains practical:

- Supabase state
- MNEMOS vectors
- GBrain or Neo4j graph edges
- GitHub commits
- PROMETHEUS decisions
- JARVIS MCP tools
- Gold Law constraints

## Oda Layer: The World Has Islands

Oda-style means the Grid is built from distinct, memorable regions with their own rules, histories, conflicts, and economies.

Each region should be:

- visually distinct
- functionally distinct
- connected to the larger map
- grounded in real user data
- able to expand without losing its identity

Example regions:

```text
The Archive Sea       -> MNEMOS memories, session history, recovered context
The Forge             -> SKADI builds, active coding work, shipped artifacts
The Signal Spire      -> ERIS entropy, drift warnings, alignment events
The Rationale Hall    -> PROMETHEUS decisions and why they were made
The Routing Gate      -> ODIN paths, project routing, next-action selection
The Rollback Vault    -> LOKI recovery points, reversibility, past states
The Treaty Market     -> public Grid agreements, cooperative economics
The Mirror District   -> HUGINN diffs, cross-session reconciliation
The Law Chamber       -> Gold Law, AEGIS constraints, Raven approvals
The Neon Frontier     -> future projects, concepts, speculative plans
```

Oda principle:

```text
Every place must have a purpose, a memory, and a route.
```

No region exists just because it looks good.

## Dante Layer: JARVIS As Virgil

Dante-style means the user does not merely search. The user journeys.

JARVIS is Virgil:

- names the territory
- explains why a path matters
- warns when the user descends into complexity
- helps the user return with meaning
- never replaces Raven authority

Traversal has levels:

```text
Surface       -> current tasks, visible context, active projects
Descent       -> old decisions, unresolved contradictions, buried memory
Trial         -> Gold Law checks, ERIS warnings, NEMESIS overlap
Reconciliation -> PROMETHEUS rationale, HUGINN diffs, user judgment
Ascent        -> simplified next action, committed plan, remembered lesson
```

Dante principle:

```text
The Grid should not only show information. It should change confusion into orientation.
```

## Tron Layer: The Interface Is Light And Law

Tron-style means the Grid has a precise digital aesthetic:

- dark negative space
- luminous routes
- identity tokens
- hard-edged geometry
- portals between systems
- visible data flow
- no clutter without function

Interface objects:

```text
Light Paths       -> graph edges between concepts
Identity Discs    -> compact memory/decision tokens
Portals           -> transitions between systems or projects
Signal Beams      -> ERIS warnings and alignment events
Circuit Rivers    -> live event streams
Archive Blocks    -> stable memory nodes
Command Gates     -> MCP tools and executable actions
Collapse Seals    -> Raven-approved final decisions
```

Tron principle:

```text
The visual layer must make structure legible.
```

Beauty serves navigation.

## JARVIS Governance Layer

The Grid must obey the same governance as the rest of JARVIS.

Hard constraints:

- no silent state mutation
- no autonomous self-modification
- no expansion without simplification
- no harvested personal data
- no public sharing without explicit opt-in
- major changes require Raven authority
- expansion must reduce complexity or improve navigation

Gold Law #7 applies to the Grid itself:

```text
No expansion without simplification.
```

If a new region, layer, or feature makes the Grid harder to understand, ERIS flags it.

## Navigation Grammar

User commands should feel natural:

```text
Take me to why Codex became Kang.
Show me the path from Pachinko Bounce to monetization ethics.
Descend into unresolved Supabase security issues.
Find the last time ERIS warned about complexity.
Open the Forge for current build work.
Return me to the simplest next action.
```

JARVIS responses should be spatial:

```text
You are entering: Law Chamber / Codex Authority / Kang

Nearby paths:
- Codex JARVIS Agent Brief
- Governed Workflow
- Event-Driven Stats
- Live Mesh Heartbeat

Warnings:
- Do not confuse execution authority with final authority.
- Raven remains the deciding layer.

Suggested ascent:
- Log significant implementation decisions through PROMETHEUS.
```

## Advanced Substrates

The Grid can eventually use spatial graphs, causal graphs, continuous fields, vector fields, hypergraphs, 4D lattice views, topology, and quantum-inspired optimization.

These are research layers, not immediate build targets. Each must make the Grid easier to navigate, remember, predict, simplify, or govern.

See `the-grid-advanced-substrates.md`.

## Build Path

Phase 0: Canon

- store this design bible
- keep The Grid marked as future concept
- keep current work focused on JARVIS stability and Pachinko Bounce

Phase 1: Text Grid

- add `jarvis_grid` MCP tool
- query memory/intake/recycle docs
- return locations, paths, warnings, and suggested next action
- no images yet

Phase 2: Graph Grid

- connect GBrain or Neo4j
- map docs, decisions, projects, and systems as typed nodes
- add ODIN routing through graph paths

Phase 3: Visual Grid

- generate location cards/images
- Tron-inspired visual language
- user inspects regions through a browser UI

Phase 4: Godot Grid

- spatial prototype in Godot 4.x
- portals, routes, memory nodes, system districts
- still grounded in real data

Phase 5: AR Grid

- overlay meaningful routes onto real work contexts
- only after hardware and privacy model are ready

## The Rule Of Awe

The Grid should feel enormous, but every step must be useful.

```text
Wonder without utility becomes decoration.
Utility without wonder becomes another dashboard.
THE GRID needs both.
```

## Current Verdict

Worth pursuing.

Not yet the main build.

The right move now is to keep feeding JARVIS clean memory, decisions, intake, graph-ready documents, and event-driven stats so the Grid has a real terrain when it is time to build the first gate.
