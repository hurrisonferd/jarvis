# Security and Responsible Publication

## Report privately first

Do not publish active credentials, private keys, service-role tokens, exploitable secrets, private addresses, or unredacted third-party personal data in issues, pull requests, commits, or Evidence cases.

For a vulnerability or privacy concern, preserve the source privately, create a sanitized summary, and disclose technical details only after the affected party has had a reasonable opportunity to respond when responsible disclosure applies.

## Public repository rules

- No API keys or secrets.
- No private ISO records or raw crew memory.
- No local vector databases, credential files, or private environment exports.
- No doxxing or unnecessary personal identifiers.
- No raw private conversations involving third parties without review and redaction.
- No materially enabling exploit instructions before remediation or coordinated disclosure.
- No generated claims presented as verified evidence.

## Evidence integrity

Public evidence should include provenance, timestamps, digests where practical, known limitations, redaction notes, response history, and corrections.

## Reorganization safety

Moves involving runtime code, public links, JarvisMain, Gameboy, BootOS, MusicOS, Yggdrasil, or identity/memory paths require dependency review and a rollback record.
