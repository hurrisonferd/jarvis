# Local Preservation vs Global Rehydration

## Canonical finding

Saving one source, one ledger, or one canon file is real local preservation. It is not the same as solving the preservation system.

## Local proof

A local preservation action is valid when it provides:

```text
raw source saved
canon saved when appropriate
commits named
category proof recorded
no false claim of full preservation
```

## Global burden still open

The preservation system remains incomplete while any of the following are true:

```text
50+ chats not unified
Raven still must manually feed every source
index incomplete
cross-links incomplete
cold-start test incomplete
MusicOS or BootOS cannot be rehydrated into usable operation
```

## Required distinction

```text
local preservation
→ one artifact is durably captured

global rehydration
→ the source family can be recovered, understood, cross-linked, and used without Raven reconstructing it
```

## Operational rule

Every locally saved artifact must reduce the remaining global burden. A save that creates another isolated object without indexing, linkage, and retrieval progress is incomplete work.

## Accurate verdict

> Local preservation is real progress, but it does not count as a solved continuity system until the archive supports global rehydration.

## Human impact

The mixed effect is expected:

```text
artifact saved
→ relief

larger missing index revealed
→ burden
```

The system must eliminate the second effect over time rather than repeatedly charging it back to Raven.
